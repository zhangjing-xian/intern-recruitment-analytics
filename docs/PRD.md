## 1. 项目概述

建立可反复使用的实习生招聘复盘工具，服务上海、广州、杭州日常招聘。用户粘贴 Excel 区域或选择本地
XLSX / CSV，经映射、清洗和确认后，在浏览器本地得到统计、对比、规则化结论及脱敏报告。

**产品定位**：面向 offer 名单的经营分析工具。输入没有简历投递、面试、成本等完整链路，
**不能**称为完整招聘漏斗平台，也**不能**计算全链路招聘转化率、渠道 ROI 或完整人效。

**核心价值**：减少重复整理；统一分母和清洗规则；给出可追溯的运营线索；默认在用户浏览器内处理数据。
本地自动结论继续使用确定性规则及模板；可选 AI 深度分析仅在主动点击、脱敏预览并确认后，
将聚合摘要直发 DeepSeek，详见第 16–20 章。

**成功标准**：同一数据、同一配置得到一致结果；用户能看懂每个指标的分母；本地导入 / 分析 / 导出
不传输招聘数据；AI 只发送本次明确确认的脱敏聚合摘要；本地结论可追溯，AI 结论另标生成来源与待核验状态。

## 2. 用户角色与使用场景

| 角色 | 使用场景 | 权限与边界 |
|---|---|---|
| 招聘HR | 每周导入、查看渠道 / 需求 / 拒 offer 问题 | 管理当前浏览器本地数据仓 |
| 招聘负责人 | 在自己的浏览器导入本人持有的数据或阅读脱敏报告 | 无远程查看他人浏览器能力 |
| 网站维护者 | 发布静态代码、维护规则说明 | 不设置数据管理后台；不接收业务数据 |

「所有人可用、各看各的数据」指不同设备 / 浏览器配置文件各自保存数据，**不是**云端账号权限系统。
相同浏览器配置文件和相同站点来源会共享存储；本地仓密码可提供静态加密保护，但**不等于**操作系统账号隔离。
共享电脑优先使用独立系统账号 / 浏览器配置文件；可提供不同加密仓，但**不得**用选择一个 HR 名称冒充身份认证。

**典型流程**：打开网站 → 选择临时分析或解锁本地仓 → 导入 → 映射 → 确认清洗及去重 → 看板筛选 →
拒 offer 排查 → 预览脱敏报告 → 下载 → 锁定或清除。

## 3. 功能范围与非功能范围

### 3.1 功能范围

1. 粘贴 TSV 表格、上传 XLSX / CSV、工作表选择、编码和分隔符预览。
2. 标准表头模板、字段自动建议和手动映射、本地映射模板。
3. 类型 / 枚举 / 日期清洗、重复确认、错误定位、有效样本说明、可撤销重算。
4. 数据集替换、新建快照、谨慎追加；数据集版本和配置版本保留。
5. 全局筛选、总览、城市、渠道 / 推荐人、HR、岗位 / 序列 / 部门、需求类型、画像、薪酬房补、时间效率。
6. 拒 offer 专项、组间对比、原因缺失分布、可解释风险组合、本地自动结论。
7. PDF（本地打印保存）、XLSX、PNG 导出；统一脱敏层。
8. 本地加密、锁定、名单与规则管理、一键清除、加密备份恢复。
9. 静态部署；PWA 离线应用壳可作为后续增强。
10. **【新增】** 可选 DeepSeek 深度分析：摘要生成、严格脱敏、完整预览、浏览器请求、结果复制 / 导出 / 加密历史。

### 3.2 非功能要求

- **安全**：默认本地模式无业务出站；AI 唯一例外是用户确认后的白名单聚合请求。不加载第三方运行时脚本 / 字体，
  不含埋点 / 广告 / 遥测 / 错误上报；AI 文本安全渲染。
- **性能验收基准**：桌面 Chrome / Edge、4 核 CPU / 8GB 内存、10,000 行 × 21 列合成数据；
  解析 + 清洗目标 ≤5 秒，筛选聚合目标 ≤500ms（预热后）；记录实际机型和测量方式，
  **不把目标宣称为已达成**。
- **文件限制**：默认 20MiB、50,000 行，均可配置；解析后也检查解压后大小 / 单元格数；
  超限阻止或提示拆分，不让浏览器卡死。
- **可用性**：中文界面；≥1280px 桌面为主要布局；键盘可操作、焦点可见、颜色外还有文字、图表配表格；
  手机可浏览概要。
- **正确性**：统一指标引擎；小数只在展示层舍入；缺失 ≠ 0；空分母显示「—」。
- **可靠性**：取消导入不改现有数据；存储失败不报保存成功；迁移失败可回退；导出失败可重试。
- **可维护性**：TypeScript 严格模式、领域纯函数、版本化口径、依赖锁文件、单元 / 集成 / 端到端测试。

### 3.3 明确不做

云账号、在线协作、共享数据库、网站数据上传接口、未经逐次确认的云 AI、自动联网补学校信息、
跨设备自动同步、第三方统计、服务器报告生成、根据风险标签自动淘汰候选人、以单一拒 offer 率
自动给 HR 绩效排序。

新模板第一行必须严格使用以下 **21 列**并保持此顺序；兼容旧表通过映射页转换。
业务表头**不增加**用户必须手填的派生字段。

| 标准字段 | 内部键建议 | 类型 / 有效值 | 缺失时处理 |
|---|---|---|---|

| 一级部门 | department | 字符串 | 未知 |
| 岗位 | position | 字符串 | 未知；禁用该行同岗位薪资基准 |
| 序列 | jobFamily | 字符串字典，可扩展 | 未知；禁用该行同序列基准 |
| 需求类型 | requirementType | 新增招聘/替补/替换/替补替换未拆分/其他/未知 | 未知 |
| 启动招聘时间 | recruitmentStartDate | YYYY-MM-DD 或 null | 日期指标排除，不排除人数 |
| 入职时间 | joiningDate | YYYY-MM-DD 或 null | 实际 / 计划语义依状态和补充字段决定 |
| 预计离职时间 | expectedEndDate | YYYY-MM-DD 或 null | 不算预计实习时长 |

| 毕业年级 | graduationYear | 四位年份或 null | 未知，不推断年龄 |
| 学历 | education | 专科/本科/硕士/博士/其他/未知 | 未知 |

**文件级最低条件**：必须识别 offer 状态列，至少有一条非空数据；缺少其他标准列要逐项告知并确认
「部分分析导入」，说明禁用的模块。全部状态未知时只允许保存待清洗数据，不生成有意义的核心率结论。
标准模板要求完整表头，**不要求**每个单元格都有值。

### 4.2 内部元数据和派生字段

不要求用户手填：`recordId`、`datasetId`、`batchId`、`sourceSheet`、`sourceRow`、`rawValues`、
`normalizationLog`、`dedupDecision`、`schemaVersion`、`rulesVersion`、`importedAt`、`dataAsOf`、
`candidateDisplayId`。

- `recordId` 是本地随机 UUID；`candidateDisplayId` 用于展示和导出，**不是**全局真实身份 ID。

派生字段：`recruitmentCycleDays`、`actualCycleEligible`、`isAccepted`、`isRejected`、`referralType`、
`housingType`、`housingAmount`、`salaryUnit`、`currency`、`salaryBenchmark`、`salaryPercentileRank`、
`isBelowMedian`、`riskTags`、`dataQualityFlags`。数据字典和口径**均版本化**。

### 4.3 字段映射机制

优先级：**标准精确匹配 → 去 BOM / 首尾空格 / 全半角差异后的匹配 → 用户已确认的别名模板 → 模糊建议**。
模糊建议**永不自动提交**。

|---|---|
| 招聘负责人 / 招聘专员 | 招聘HR |

| 部门 / 事业部 | 一级部门（确认层级） |
| 职位 / 岗位名称 | 岗位 |
| 招聘启动日期 | 启动招聘时间 |
| 到岗日期 | 入职时间 |
| 候选人姓名 | 姓名 |
| 毕业年份 | 毕业年级 |
| 毕业院校 | 学校 |
| 招聘渠道 / 来源渠道 | 渠道 |
| offer薪资 | 薪资 |
| 住房补贴 | 房补 |
| offer进度 | offer状态 |
| 拒offer原因 | 拒绝原因分类 |

约束：

- 「学历 / 学位」「推荐人 / 招聘HR」「入职时间 / offer 接受时间」**不能**互相自动映射。
- 两个源列竞争一个目标字段时**必须选择或显式合并规则**，不静默覆盖。
- 多余列默认忽略，不能意外导出；可映射到已定义的扩展字段。
- 模板保存源表头签名、字段映射、枚举 / 单位规则和版本，**不存示例候选人数据**。

## 5. 数据清洗、导入和重复处理

### 5.1 解析与类型

- **上传指浏览器读取本地 File，不创建网络上传**；粘贴仅通过输入框 / 明确粘贴动作，不后台读取剪贴板。
- XLSX 显示工作表、可见 / 隐藏状态和行列数，用户选择表及表头行；默认第一行，空行跳过并计数；
  隐藏行 / 列**不默默排除**，显示是否包含选项。
- XLSX 只读值和已有缓存结果，**不执行宏、公式、外部链接**，不联网更新。关键列公式无缓存时
  提示转值后重传；有缓存也标记可能陈旧。
- CSV 默认 UTF-8，允许用户选择 GB18030 等受支持编码；正确处理 BOM、引号、逗号、制表符、字段内换行；
  粘贴 TSV 同样尊重带引号内容。
- 数字字段**不使用隐式 JavaScript 转换**；空白、`-`、`N/A` 按配置视为 null，负薪资 / 无穷值报字段错误；
  工资带范围时保留原文并要求确认，**不擅取中点**。
- 清理首尾空白和不必要换行；学校、岗位等语义不相同的文本不做激进合并，
  岗位项目代号**不能自动删除**。

### 5.2 日期

- Excel 读取工作簿 1900 / 1904 系统；**仅日期列**转换数字序列，**需求ID 绝不转换日期**；
  1900 系统异常序列 60 按无效日期提示。
- 支持明确 `YYYY-MM-DD`、`YYYY/MM/DD`、`YYYY年M月D日` 及合法 Excel 日期。
  `01/02/2026` 等歧义要求确认日月顺序，**不凭系统区域猜测**。
- 统一为无时区日期字符串，以日历日序号相减，避免夏令时 / UTC 转换少一天；同日为 0 天。
- 入职早于启动、预计离职早于入职为错误；保留行进入计数，但排除受影响周期，显示错误数。
- 分析截止日 `dataAsOf` 由用户确认，默认导入当日；「已入职」但入职日晚于截止日标记矛盾，
  不自动改状态，周期排除至确认；其他状态未来计划入职正常。
- 超长周期默认 >180 天提示核实，**不自动截尾或删除**；若有效仍参与周期，并展示中位数 / P75 和异常数。

### 5.3 状态与单位

- 状态按明确字典统一：`已送审批 → offer审批中`；「审批通过」**不等于**候选人接受；
  离职、撤回、取消等进入「其他」并保留原值，除非用户明确定义另一个口径版本。
- 薪资计薪口径的选项是「人民币元/月」「人民币元/天」「其他」「暂不确定」，
  **默认「人民币元/月」**（用户反馈 ①，2026-09-27 确认；此前默认「暂不确定」）。
  默认值只给**币种**与**计薪周期**两列取值，**不做任何换算**，也不逐行猜单位；
  名单里若混有按天计薪或外币的行，用户必须自己在清洗口径里改（改成「人民币元/天」「其他」或「暂不确定」）。
  选「暂不确定」时只展示未确认原值概况，**禁用待遇对比及低薪风险标签**。
  默认值带 `confirmedAt = null`，界面据此说明「还没手动改过」，不会假装是用户确认的结果
  （口径与理由见 `docs/DECISIONS.md` D-095）。
- 混合月薪 / 日薪**不得直接聚合**；未提供计薪天数和明确换算规则不换算。每条记录保留单位，分别展示。
- GPT 字段以原值优先，缺失可用本地名单匹配；**不在名单只有当用户声明名单完整且采用「名单模式」时**
  才判否，否则仍未知。冲突要展示，两种来源都保留。

### 5.4 重复、替换和追加

- 原始完全重复与清洗后疑似重复**分别展示**。完整相同记录默认建议「每组保留首条」，
  **必须确认后生效**；原始数据和去重决策可回溯。
- **不用需求ID 单独去重**；同需求多个候选人是合法的。**同姓名也不能认定同一个人**。
- 缺少 offer 唯一 ID 时，`需求ID + 姓名 + 启动日期` 只可作为**疑似键**，不作为自动合并主键。
- 新导入默认「新建快照」或明确「替换当前数据集」，**不自动累计历史文件**；
  同一历史名单反复导入不会自动让总数增长。
- 追加模式先展示重复与状态冲突。无稳定 `offerId` 时不自动把已审批、待入职、已入职合并为同一 offer；
  让用户决定保留 / 替换 / 另建快照。
- 每次提交为事务：解析预览、确认、生成新版本、成功后切换；**失败不破坏旧版本**。

### 5.5 质量分级

| 级别 | 情形 | 处理 |
|---|---|---|
| 阻断 | 文件无法解析、无数据、缺 offer 状态映射、目标列冲突、超限 | 停止导入 |
| 字段错误 | 非法日期 / 薪资 | 仅排除对应指标 |
| 警告 | 未知枚举、缺失、超长周期、疑似重复、计划日期语义 | 提示并保留 |

质量页显示：原始行数、空行数、保留行数、去重行数、异常行数、各指标有效样本数，
支持按问题过滤并**定位原始行号**。

## 6. 指标口径与计算公式

### 6.1 统计粒度和分母

默认一行代表**一次 offer 相关记录**，不代表唯一候选人或完整需求。审批中也在名单中，
因此总卡片命名「**总 offer 记录数（含审批中）**」，提示不等于正式发放 offer 数。

在当前数据集、筛选条件和去重策略下：

```
N  = 所有保留记录
J  = 已入职
P  = 待入职
A  = offer 审批中
R1 = 拒绝 offer
R2 = 拒绝口头 offer
R  = R1 + R2
U  = 其他 / 未知
D  = J + P + R          ← 核心分母，排除审批中、其他、未知

恒等式：N = J + P + A + R1 + R2 + U
```

| 指标 | 公式 / 规则 | 展示说明 |
|---|---|---|
| 是否接受 offer | 状态 ∈ {已入职, 待入职} | 派生布尔；未知状态为 null |
| 是否拒 offer | 状态 ∈ {拒绝offer, 拒绝口头offer} | 派生布尔；未知状态为 null |
| 接受数、接受率 | J+P；(J+P)/D | 接受不等于实际入职 |
| 拒 offer 率 | R/D | D 排除审批中、其他和未知 |
| 入职率 | J/D | **不使用 J/N 冒充**此指标 |
| 待入职占比 | P/D | 默认采用核心率分母；另可显示 P/N 并明确「占全部记录」 |
| 审批中占比 | A/N | 明示分母不同 |
| 状态结构占比 | 各状态数/N | 用于状态图；含其他 / 未知 |
| 名单覆盖需求数 | countDistinct(非空需求ID) | HR 内按本 HR 记录去重；跨 HR 相加可能超过全局 |
| 招聘周期天 | 入职日期 − 启动日期 | 日历日，不是工作日；日期合法且非负 |
| 平均实际招聘周期 | Σ 合法周期 / 有效已入职样本数 | 默认仅 J，显示有效 n 和排除数 |
| 待入职计划周期 | P 中合法日期差的均值 / 中位数 | 单独显示，不能混入实际周期 |
| 预计实习天数（可选） | 预计离职 − 入职 | 仅计划，不能称实际留存 |
| 原因填写率 | 有有效原因的拒 offer 数 / R | 非拒 offer 不入分母 |

处理规则：

- N 或 D 或相关有效 n 为 0 时，显示「**—/无有效样本**」，**不显示 0%**。图表需要保留计数为 0 的状态。
- 平均数 / 金额展示两位小数，人数整数，率两位小数；**内部保留完整精度**。
- **汇总率必须合计分子分母再相除，不能平均各城市百分比。**

### 6.2 同岗薪酬基准

严格同组：`城市 + 序列 + 规范化岗位 + 币种 + 计薪周期`。

- 参照集合默认是当前数据集及时间范围中的**全部保留状态记录、有效薪资**；
  **不受渠道 / HR / offer 状态 / 薪资筛选影响**，避免切换「拒 offer 组」导致基准漂移。
  参照集合定义和版本显示在图旁；业务筛选影响展示对象，不静默改变基准。
  若用户切换基准范围**必须显式记录**。
- 默认参照有效样本 **n≥5** 才出基准；n<5 显示「同岗样本不足」，**不打低薪标签**；
  不自动扩展到不同岗位。以后可选择同城市同序列回退，但必须标记回退层级。
- 分位数用线性插值：

```
Q(p)：排序 x0…x(n−1)，h = (n−1)·p，j = floor(h)
Q = xj + (h − j) × (x[min(j+1, n−1)] − xj)
P25 / P50 / P75 由此计算
```

- 薪资分位排名采用**并列中位秩**：`[小于该薪资数 + 0.5 × 等于该薪资数] / n × 100%`；
  与分位数值是两个概念。
- 低于中位数 = `salary < P50`；**相等不标低**。样本含自身，这是描述性定位，非独立预测。
- 「薪资 + 现金房补」仅在同币种同周期且金额明确时计算；**住宿不折算成现金**。
  房补缺失时总额未知，**不能填 0**。

### 6.3 分层维度和全局筛选

城市、渠道、推荐类型、HR、岗位、序列、部门、需求类型、毕业年级、学历、学校、GPT、薪资区间、
房补类型**均复用相同聚合函数**：N/J/P/A/R/D、入职率、拒 offer 率、有效周期 n 和均值。

- 不同字段间 **AND**，同字段多选 **OR**；未选择某字段等于不过滤，**未知是可选的独立值**。
- 状态筛选会改变 D，应明确提示「**当前子集率**」；专项比较默认采用未加单组状态筛选的当前人群，
  若已有单组筛选，提示切换，**不暗中清除**。
- 时间默认不筛选；用户选择时默认按**启动招聘日期**，可切换**入职日期**，并显示选中基准。
  日期缺失数单列、提供纳入未知选项。
- 没有 offer 发出日期**不能**显示「本月发 offer 趋势」；按入职日期筛选也**不能**称发 offer 批次表现。
- `dataAsOf` 是数据快照声明，**不能**仅凭当前状态还原历史某日状态。

- 导出说明：Excel / Markdown 只出数据表不出图，PNG / 打印 PDF 里的图是**导出时按固定顺序
  生成的静态图**，不保证与屏幕上的排序与横竖方向逐一相同（见 `docs/KNOWN_ISSUES.md`）。

**自动结论结构**：观察（指标 + 计数）→ 比较对象与百分点差 → 数据限制 → 建议验证行动。

> 示例：该渠道拒 offer R/D，高于整体 x 个百分点；样本 D 偏小，建议核对同岗位薪资和拒绝原因后
> 再调整投入。

所有数值由引擎生成；无证据时生成「暂无法判断」及补数据建议。

## 9. 拒 offer 专项分析设计

### 9.1 分析人群

- **拒 offer 组** = 拒绝 offer + 拒绝口头 offer；**入职组** = 已入职。
- 待入职与审批中**不进入**这两组比较，但待入职依用户定义**仍在**拒 offer 率分母 D 中。
- 页面必须明确「**组间比较人群**」和「**核心率人群**」不同。

对每个维度同时给出两种视角：

1. **组内构成**：某特征在拒 offer 组的记录数 / R，对比该特征在入职组的记录数 / J；
   这是**画像构成**，不能称该特征拒 offer 率。
2. **特征内结果**：该特征拒 offer 数 / 该特征 D，同时展示入职率、待入职数和样本量。

比较维度：渠道、推荐类型、HR、岗位、序列、部门、需求类型、年级、学历、学校、GPT、薪资、房补。
数值用有效 n、中位数、P25/P75 及分布；类别用计数、比例和百分点差。
薪资对比在同城市 / 序列 / 岗位 / 单位内优先展示，混合总体仅描述。

### 9.2 原因分析

默认**一行一个主要原因**：薪酬、住房 / 住宿、其他 offer、岗位内容、地点、实习时间、学业安排、
个人原因、其他、未填写。可维护字典但**不凭候选人背景推断原因**。多原因扩展需明确主因或多选统计，
不能混用分母。

- 饼 / 条形图以**全部拒 offer 记录 R 为分母**，包含「未填写」；可另提供已填写原因分布并标明有效 n。
- **当前新附件 7 条拒 offer 的原因全缺失**：应显示原因填写率 0%，本地与 AI **都不得**输出
  「主要因为薪资」。

### 9.3 风险标签与组合

名称建议为「**拒 offer 运营关注标签**」，页面解释这是**规则筛查**，不是个人概率模型，
**不用于**自动淘汰或歧视候选人。GPT、学校、学历**仅作聚合复盘特征**，不单独触发个人高风险。

基础条件：

- GPT 为「是」；
- 房补类型明确为「无补贴」；
- 同岗有效薪资低于 P50；
- 招聘等待超阈值。

**未知条件保持 unknown，不当 false 或零补贴。**

时间条件必须区分：

| 情形 | 口径 |
|---|---|
| 已入职实际周期 >30 天 | 可用于事后描述 |
| 待入职 / 审批中 截至日 − 启动日 >30 天 | 叫「当前等待时长」 |
| 拒 offer | 因缺少拒绝日期，历史等待标签为**未知** |

不能用入职后的结果作为预测特征，也不能把当前等待算成历史拒 offer 周期。

可配置组合示例：`GPT + 无补贴 + 低于同岗 P50`；`无补贴 + 低薪`；`低薪 + 当前等待 >30 天`。
阈值 30 天仅为初始运营规则，用户可改，并随报告记录。**提供住宿不命中「无补贴」条件。**

**历史组合结论门槛**：组内 D≥10、拒 offer≥3，且组内拒 offer 率比同基准总体高 ≥10 个百分点，
才输出「观察到较高拒 offer 关联」；否则只显示描述或样本不足。只在可比较状态均可观察的特征上评估组合，
**不将缺失时间字段当未超时**。多个组合探索产生的线索**不是**显著性检验。

每条风险输出包含：规则 ID / 版本、命中条件、未知条件、命中记录数、有效 D/R、比较基准、率差、
适用范围、建议核查事项。**禁止**输出「此人拒 offer 概率 80%」等未经训练和校准的概率。

### 9.4 行动建议

规则化建议映射：

| 观察 | 建议 |
|---|---|
| 原因缺失 | 补充拒绝访谈 |
| 同岗低薪关联 | 核查报价与同岗基准 |
| 无补贴关联 | 核查住宿需求与补贴资格 |
| 审批记录较多 | 梳理审批节点 |
| 等待过长 | 跟进当前节点 |
| 小样本 | 继续采集 |

**不得**把学校标签直接转成「不招聘该类学校」。

## 10. 数据安全与隐私方案

### 10.1 安全承诺及边界

默认招聘文件、清洗、统计和报告**在浏览器内完成**。

AI 是唯一例外：仅在主动点击并确认**完整脱敏预览**后，浏览器把**聚合摘要及认证 Key** 发往 DeepSeek；
不发原始明细、不经网站服务器、不做远程日志。Key 本地管理，认证时发送给 DeepSeek，
**不等于绝不离开设备**。静态服务器仍接收加载资源所需的 IP 等元数据。自有代理如启用也是独立接收方；
**不得**承诺绝对匿名、供应商零保留或本地清除能撤回已发内容。完整隐私文案见第 20 章。

IndexedDB 按来源隔离，**不能**把同一来源的不同 URL 路径当作安全隔离。GitHub Pages 同账号不同项目
通常共享来源，应优先独立域名 / 来源，避免与不可信应用同源。加密可保护落盘数据，
但**不能**防止解锁时的恶意扩展、XSS、已被控制的设备或篡改后的站点代码。

### 10.2 两种本地存储模式（AI 开关独立）

| 模式 | 行为 |
|---|---|
| 临时模式 | 默认可直接分析，只在内存，刷新 / 关闭即丢失；不自动写入业务数据 |
| 加密本地仓 | 用户设置密码后持久化；生产版**不提供**默认明文落盘。密码不可找回，先提示可下载加密备份；新浏览器无法自动读取旧浏览器数据 |

**AI 默认关闭**。临时模式 Key 只在内存；选择持久化 Key 或保存 AI 历史**必须使用加密仓**，
不能为了新功能降低原加密要求。

### 10.3 加密设计

- Web Crypto API：**PBKDF2-HMAC-SHA-256** 由密码派生 **AES-GCM 256 位**密钥；
  随机 salt ≥16 字节，每次加密生成独立 **12 字节 IV**，禁止同密钥复用 IV；**128 位认证标签**。
- PBKDF2 迭代次数做本机基准并持久化，初始建议 **600,000** 次并测试可用性；
  该值是本方案初始配置，**不是**永久安全保证。
- 加密信封存储：`formatVersion`、`schemaVersion`、kdf 参数、salt、iv、ciphertext 及最小非敏感随机标识。
- 候选人数据、原始预览、HR / 岗位、文件名、清洗记录、分析缓存与敏感自定义规则**均在密文中**；
  **不对明文姓名 / 薪资建立 IndexedDB 索引**。AES-GCM 附加认证数据绑定仓 ID 和版本，防止信封错配。
- 密钥不可导出且只驻留内存，**不保存**密码或解锁密钥到 localStorage / IndexedDB。
  **API Key 仅可加密存储**，不能与解密密钥一并落盘；历史**不得**包含认证头。
- 解锁后内存计算；手动锁定、刷新、默认闲置 **15 分钟**锁定。锁定时清空可控状态和图表缓存、
  撤销 Blob URL；JavaScript 无法保证物理内存取证级擦除，**不能夸大**。
- 密码错误 / 密文被修改均以**解锁失败**处理，不输出原始敏感内容。改密：先校验旧密码，生成新 salt
  和密钥，重新加密并事务替换，失败保留旧仓；禁止部分数据用新密码、部分用旧密码。
  敏感持久化状态更新也必须使用**新 IV**。

### 10.4 出站控制和前端防护

- 所有依赖、图标、字体、图表、Worker 脚本**打包同源**；禁止 CDN 脚本、在线字体、在线图片、地图、
  远程错误上报。
- 用户输入通过 React 文本渲染，**不使用 `dangerouslySetInnerHTML`**；不执行表格公式、
  不激活原始单元格链接；CSV / XLSX 导出防公式注入。
- **生产 CSP 原则**：
  - `default-src 'self'`；`script-src 'self'`；`object-src 'none'`；`base-uri 'none'`；`form-action 'none'`；
  - `img-src` 仅 `self` / `blob:` / `data:`；Worker 仅 `self`；外部字体禁用；
  - **仅本地版**：`connect-src 'none'`；
  - **含可选 AI 版**：精确允许 `https://api.deepseek.com`，仍须应用层逐次确认（见 18.6）；
  - 样式若图表确需内联需单独限定 style 策略，**不放开** script 的 `unsafe-inline` / `eval`。
- PWA 预缓存可能需要读取同源静态资源，须单独设计 Service Worker 请求策略与 CSP；
  若 PWA 必须额外允许 `connect-src self`，要限定静态路径及无数据载荷，并用网络测试验证。
  **不得**为 PWA 一键放开所有网络。
- 能配置响应头的平台使用响应头 CSP 及 `frame-ancestors 'none'`；GitHub Pages 的 meta CSP
  有能力限制，**不能**声称提供完全等价响应头保护。
- 无第三方统计，包括托管平台的可选 Web Analytics / Insights；构建 / CI 只处理合成数据和代码，
  不包含真实招聘附件、密码、真实截图或备份。

### 10.5 本地备份、清除及存储边界

- 浏览器可能回收存储，用户清理站点数据 / 无痕窗口退出也可能丢失。显示容量与持久存储申请结果，
  **不承诺永久保留**；提供本地加密备份和导入恢复，**不能**把备份上传到站点。
- **一键清除**以明确确认弹窗列出影响：当前应用全部本地仓、原始 / 清洗数据、映射、学校名单、
  分析缓存、偏好、IndexedDB、应用自己的 localStorage、Cache Storage 和 Service Worker。
  先通知并关闭其他标签页连接，再删除；被占用则提示关闭标签并重试。**只清本应用命名空间**，
  不删除同源其他应用。内存及 Blob URL 同时清理，页面回到空状态。**无法删除用户已下载的报告 / 备份**，
  应明确告知。
- **清全部**包含加密 Key、AI 历史与在途任务；单独清 AI 历史不删招聘源数据或 Key；
  清除后**忽略迟到响应**，且**不能**撤回 DeepSeek 已接收内容。

### 10.6 报告默认脱敏

- 默认导出**聚合报告**，不导出逐条明细。需要明细时姓名替换为报告内候选人 ID；
  没有可靠人员 ID 时实际是**记录级代号**，避免声称跨批次是同一人。
- 薪资固定区间默认为 `<3000`、`[3000,4000)`、`[4000,5000)`、`[5000,6000)`、`≥6000`，
  仅针对确认「人民币元 / 月」；其他单位使用独立配置。**准确中位数等在外发报告也改为区间或隐藏**，
  避免间接恢复原值。
- 同时默认隐藏需求 ID、具体推荐人、自由文本原因和原始行数据；HR 用 HR 代号；
  学校 / 岗位小组 `n<5` 合并或抑制，防交叉识别。必要时做**互补抑制**，避免用总计减去其他组还原小组。
- 自由文本原因**不能**只替换姓名就直接导出，默认仅导出标准原因分类。
  公司部门 / 岗位是否保留可由用户在预览选择。
- 同一导出文件内代号稳定，**跨报告默认重建**；对照表**不导出**。
  脱敏是降低暴露，**不承诺**不可重新识别。
- 导出前先构造唯一 `SanitizedReport` 模型，所有格式从该模型生成，
  **不允许** PNG 截图原始页面或 XLSX 隐藏 sheet 保留原文。
  tooltip、图注、文件名、PDF 元信息、导出日志同样不包含敏感字段。
- 报告下载后由用户控制，站点加密**不等于**导出文件已加密；
  默认不提供「一键原始数据报告」，加密备份与脱敏报告是**不同入口**。

## 11. 报告导出方案

### 11.1 报告结构

1. 标题、数据集版本、时间范围、生成时间和数据截至日；
2. 数据口径（分母定义、去重策略、规则版本）；
3. 核心 KPI；
4. 分维度分析；
5. 拒 offer 专项；
6. 自动结论与行动建议；
7. 数据质量与限制（有效样本、未知比例、异常）。

### 11.2 格式与实现

| 格式 | 实现 | 要点 |
|---|---|---|
| PDF | 专用打印版式 + `window.print()` | 页面提示选择「另存为 PDF」；需支持中文字体、分页、页眉页脚和图表 |
| Excel | SheetJS / `xlsx`，多工作表 | 使用脱敏数值 / 区间；强制单元格类型防公式注入；**不得**隐藏原始数据 sheet |
| 图片 | 离屏渲染脱敏 ECharts 快照导出 PNG | 按图表组件真实尺寸和 DPI 渲染；可加水印；**不能**直接截图原始看板 |

三种格式使用**同一筛选、同一数据版本、同一口径**，由唯一 `SanitizedReport` 模型生成，
**避免数值不一致**。导出前均提供预览。文件名不含敏感信息。

### 11.3 结论文本模板

结论由规则生成，例如「在 D 条核心记录中，X 渠道拒 offer 率 R/D…」。
无足够数据时**显式说明**缺少什么，不给结论。结论必须能回看分子 / 分母。

### 11.4 导出限制

- 默认不导出姓名、准确薪资、具体推荐人、需求 ID、自由文本原因和原始文件行；
- 明细只在用户明确选择时导出，且使用报告内 ID；
- 小样本和未知比例必须在报告中标明；
- 导出**不经过服务器**。

### 11.5 导出验收要点

- 同一筛选下 PDF / Excel / PNG 数值一致；
- PDF 中文不乱码、分页正确；
- Excel 无公式注入、无隐藏明细 sheet；
- PNG 只含脱敏图表；
- 文件名 / 元信息 / 图注无敏感字段；
- 用合成哨兵字符串（如姓名、薪资、HR 名）检索导出内容，必须无命中。

## 12. 测试与验收标准

### 12.1 附件核对验收

新附件保留 83 行，第 2 行状态归未知且不进 D，其余映射按第 0 章，得到单列新版基线；
没有完全重复，不执行旧附件去重。异常行需用户核实，不自动删除。开发仓库不得提交真实附件，
可在用户设备本地手工核对这些聚合结果。

### 12.2 最小合成验收集

6 条记录的状态依次为已入职、已入职、待入职、offer审批中、拒绝offer、拒绝口头offer；
两条已入职周期分别 10 和 20 天，其余日期不进入实际周期。

预期：N=6，J=2，P=1，A=1，R=2，D=5；接受率 60%，拒 offer 率 40%，入职率 40%，
待入职占比 20%，审批中占比 16.67%，平均实际周期 15 天。追加 1 条其他状态：N=7、D 仍 5、核心率不变。

薪资合成例：同岗同单位 3500、4000、4000、4500、5000，P25=4000、P50=4000、P75=4500；
仅 3500 低于中位数；4000 分位排名 40%；同组 n=4 时基准不足。
住宿记录不视为无补贴，未知房补不视为 0。

以上为**开发回归基准**（步骤7 起用于单测），与 12.1 的真实附件聚合基线分开。

### 12.3 功能与边界验收矩阵（A01–A20）

| 编号 | 验收场景 | 通过条件 |
|---|---|---|
| A01 | XLSX/CSV/粘贴三种同内容输入 | 标准化输出一致，原始来源可追溯 |
| A02 | 重复表头、缺状态列、空表 | 定位问题并阻断；不破坏原数据 |
| A03 | 标准/别名/模糊映射 | 精确匹配自动建议；模糊和冲突需确认 |
| A04 | 1900/1904、歧义日期、闰年、负周期 | 正确转换或报错；日期不偏移一天 |
| A05 | 相同需求不同候选人 | 不被错误去重 |
| A06 | 未知状态/空分母/缺日期 | 不造 0%，保留有效计数和样本排除说明 |
| A07 | 多级筛选、图表下钻、导出 | 共用筛选快照，指标完全一致 |
| A08 | 单 HR、原因全空、样本不足 | 显示限制，不输出排名或原因猜测 |
| A09 | 混合薪资单位、住宿、未知房补 | 不跨单位合算，不把住宿计为无待遇 |
| A10 | 拒 offer 组 vs 入职组 | 构成比与特征内拒 offer 率明确区分 |
| A11 | 正确/错误密码、密文篡改、刷新 | 正确解锁；失败无明文；刷新需重解锁 |
| A12 | IndexedDB/缓存检查 | 无明文候选人、薪资、HR、文件名或敏感规则 |
| A13 | 两个独立浏览器配置文件 | 导入 A 不出现在 B；同配置共享边界有说明 |
| A14 | 本地/AI 两种模式网络观察 | 本地无业务出站；AI 仅一次确认正文到指定端点；Key 仅认证头，其他出站禁止 |
| A15 | 恶意 HTML、表格公式注入 | 不执行脚本或公式，不产生外部请求 |
| A16 | PDF/XLSX/PNG | 中文完整，无截断；明细/隐藏数据/元信息无原始敏感内容 |
| A17 | 清除 + 重开 + 其他标签页 | 本应用数据全空，失败可见；不恢复旧数据 |
| A18 | 锁定/改密/存储失败/迁移失败 | 不丢旧仓，不留下明文或半写入状态 |
| A19 | 生产构建、子路径、刷新、断网 | 正常打开；PWA 安装后已缓存功能离线可用 |
| A20 | 性能基准 | 记录真实结果；超目标说明瓶颈并修复，无静默跳行 |

网络测试同时检查请求 URL、请求体、资源类型和触发动作。用合成哨兵字符串覆盖姓名、薪资、HR 等，
并在存储 / 导出 / 网络中检索；**仅看「没有 POST」不算通过**。

### 12.4 测试方式

- **Vitest**：日期解析、分母 / 率、分位数、重复检测、缺失处理、风险规则、脱敏规则等纯逻辑；
- **Testing Library**：映射确认、错误提示、筛选交互、空态 / 锁定态；
- **Playwright**：导入 → 加密保存 → 刷新解锁 → 分析 → 脱敏导出 → 清除的端到端流程；
- 网络监听：断言默认零出站；仅确认后的 AI 请求命中白名单端点；
- 存储检查：断言 IndexedDB / localStorage / Cache 中无明文敏感数据；
- 性能基准：大表导入、聚合计算和图表渲染的耗时基线。

**只用合成数据**，真实个人数据不得进入测试与仓库。

### 12.5 隐私与网络专项核验

- 抓取网络请求，确认默认无外部请求；
- 用合成哨兵（姓名、薪资、HR、文件名）检索 IndexedDB、localStorage、Cache、导出文件；
- 检查错误日志与控制台不输出敏感数据；
- 检查 Key 不出现在持久化、日志、URL 和报告中。

## 13. 技术方案

### 13.1 前端技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 构建 | Vite 8 + TypeScript（strict） | 快、简单、纯静态产物 |
| UI | React 19 + React Router（HashRouter） | 静态托管刷新不 404 |
| 样式 | Tailwind CSS v4（`@tailwindcss/vite` 插件） | 无额外构建链 |
| 图表 | Apache ECharts（本地打包） | 功能全、可离屏渲染 PNG |
| 表格解析 | SheetJS / `xlsx`（本地打包） | 只读值、不执行公式 |
| 本地存储 | IndexedDB（Dexie 封装）+ Web Crypto | 事务、版本迁移、加密信封 |
| 状态 | React Context + 自定义 hook（必要时 Zustand） | 数据量适中，避免过度抽象 |
| 测试 | Vitest + Testing Library + Playwright | 单测 / 组件 / 端到端 |
| AI | `fetch` 直连 DeepSeek（唯一网络适配器） | 无后端，逐次确认 |

Node 要求 20.19+ / 22.12+（本机 v24.19.0 满足）。

### 13.2 依赖与实现原则

- 所有依赖本地打包，**不使用 CDN**；生产构建产物可直接托管到静态平台。
- `package.json` 锁定版本；新增依赖须先确认收益与体积。
- 关键库版本在**步骤1 实施时按官方文档核实后锁定**（见 `docs/DECISIONS.md`）。
- 纯函数优先：指标、清洗、脱敏逻辑不依赖 React / DOM / 浏览器存储，便于测试。
- 不使用 `dangerouslySetInnerHTML`；AI 结果按安全 Markdown 白名单渲染。
- 新增任何网络请求必须走统一适配器并受 CSP 与确认机制约束。

### 13.3 部署方式

| 平台 | 说明 |
|---|---|
| GitHub Pages | 子路径 `base`，HashRouter，meta CSP 能力有限 |
| Cloudflare Pages | 可配置完整响应头，建议首选 |
| Vercel | 静态部署，不建 Functions / API Route |
| 本地 | `npm run preview` 或直接打开构建产物 |

**不为部署引入网站后端、上传接口或数据库**。生产环境关闭托管平台分析统计。

### 15.5 建议补充字段与缺失替代方案

保持 21 列模板不变，以下作为**可选扩展列或导入设置**，不要求一次性全部补齐。

| 建议字段 | 用途 | 没有时的替代方案 |
|---|---|---|
| offer 唯一 ID | 跨次导入去重、状态更新 | 新建快照 + 疑似重复人工确认，不自动合并 |

## 16. AI 深度分析功能设计（可选、默认关闭）

### 16.1 定位与总原则

AI 是**可选增强**，不是核心链路依赖。默认关闭，开启与每次调用都需用户明确操作。

- 统计口径**始终**由本地引擎计算，AI 只做解读与建议，**不允许覆盖或改写本地数字**；
- 只发送**聚合脱敏摘要**，不发送原始明细、姓名、准确薪资、需求 ID 和自由文本；
- 每次发送前展示**完整预览**（含 JSON、提示词、模型参数、目标地址），确认后才请求；
- 无后端转发，浏览器直连 DeepSeek；网站服务器不接收任何摘要内容；
- 请求失败、超时、取消都不自动重试、不自动降级到其他模型或代理；
- 关闭 AI 不影响任何本地功能。

### 16.2 交互流程

```text
看板 → 点击「AI 深度分析」
     → 本地生成候选聚合摘要（纯本地，无网络）
     → 脱敏引擎按隐私级别净化（k≥5、分桶、代号）
     → 完整预览弹窗（JSON / 提示词 / 参数 / 目的地 / 脱敏说明）
     → 用户点击「确认并调用 DeepSeek」
     → 单次请求（绑定预览 hash，只能消费一次）
     → 结果校验与安全渲染
     → 用户可选：复制 / 导出 / 显式加密保存到历史
```

任何一步参数变化（筛选、模型、参数、隐私级别、摘要内容）都必须**重新生成预览**，
旧预览与确认立即失效。

### 16.3 数据边界

| 允许发送 | 禁止发送 |
|---|---|
| 聚合计数、率、分母、有效 n | 姓名、手机、邮箱等身份信息 |
| 分桶后的薪资与周期 | 准确薪资、准确中位数值 |
| HR 代号、职位 / 部门类别 | HR 真实姓名、需求 ID、候选人 ID |
| 学校层次、原因主题类别 | 学校全名长尾、自由文本原文 |
| 质量与口径说明 | 原始行、文件内容、文件名、原始错误行 |

再识别防护：

- 任何单元格 `n<5` 抑制（不填 0，直接省略并标注）；
- **互补抑制**：结合总计避免反算小单元；
- 跨表检查：同一维度在多个表中出现时，避免组合还原；
- 高维稀疏表降维或不上传；
- 无法安全发布时，**宁可降级为更粗的聚合，不降低 k**。

### 16.4 结果质量与信任

- 结果页固定四大章节：**现状判断 → 主要问题 → 可能原因 → 行动建议**，末尾**必须**附数据限制；
- 每个数字标注来源 `metricId`；页面对关键数值与本地统计**做一致性核验提示**，
  不一致时提示用户以本地看板为准；
- AI 结果**不能**作为唯一决策依据，页面必须显示免责说明；
- 若响应被截断（`finish_reason=length`），明确标记「结果不完整」；
- `reasoning_content` 默认**不展示、不保存**，除非用户显式开启；
- 不默认保存历史，保存需用户显式点击，且写入加密仓。

### 16.5 历史记录

保存字段：时间、模型、请求与返回模型、隐私级别、数据范围与筛选摘要、规则 / 提示词版本、
已发送摘要（脱敏后）、结果正文、`usage`、`finish_reason`。

- **禁止**保存 Key、认证头、原始明细；
- 历史可离线查看；删除单条、清空历史、清全部为**独立操作**，作用范围必须在 UI 说清；
- 清空历史**不删除**招聘源数据与 Key；删 Key **不删除**招聘数据；
- 清空时中止在途请求并**忽略迟到响应**，避免已删除内容被写回。

### 16.6 失败与降级

| 情形 | 处理 |
|---|---|
| 未配置 Key | 引导到设置，不发起请求 |
| 401 / 402 | 提示 Key 无效或余额问题，不自动重试 |
| 429 | 提示稍后重试，不自动轮询 |
| 5xx | 提示服务端问题，保留预览供重试 |
| 疑似 CORS / 网络失败 | 给代理配置说明，**不硬判为 CORS**，不自动切换 |
| 空 / 非 JSON / 截断响应 | 提示异常并保留原始错误摘要（不含敏感内容） |

**不自动重试、不自动换端点、不自动换模型。**

## 17. AI 摘要结构与提示词设计

### 17.1 摘要生成原则

摘要由**本地聚合接口**生成，字段白名单固定，附 `metricId`、样本量与分母说明。

- 只包含预定义表，禁止附全量 store、历史、原始错误行；
- 体积预算：默认 **128 KiB**，每维 Top10，默认最多 2 个交叉维度；
- 超限时**本地**调整维度或时间范围，重新生成预览，**不静默截断**；
- 生成固定正文与 `hash`，预览、请求与历史共用该 hash，保证发送内容可复现；
- 元数据（文件名、筛选值、HR 名）也**必须**脱敏后才能写入 `scope` 说明。

### 17.2 摘要结构（示意）

```jsonc
{
  "schemaVersion": "ai-summary/1",
  "privacyLevel": "standard",          // strict | standard | custom
  "dataAsOf": "2026-08-31",
  "scope": {
    "rowCount": 128,
    "dedupPolicy": "keep-first",
    "filters": { "city": ["上海", "广州", "杭州"] },
    "ruleVersion": "metrics/1.2.0"
  },
  "kpi": { "N": 128, "J": 41, "P": 9, "A": 6, "R1": 5, "R2": 2, "D": 57 },
  "dimensions": [
    { "metricId": "channel.reject_rate", "dim": "channel",
      "rows": [{ "key": "官网", "N": 40, "D": 18, "R": 6 }] }
  ],
  "housing": [{ "key": "无补贴", "N": 30, "D": 12, "R": 5 }],
  "rejectionReasons": [{ "key": "未填写", "count": 7 }],
  "quality": { "unknownStatus": 0, "missingSalary": 21 },
  "limits": ["部分城市 D<10", "原因填写率 0%"]
}
```

### 17.3 提示词设计

- System：角色为招聘数据复盘助手；只能用给定指标；不得编造数字；
  必须区分「组内构成」与「特征内率」；样本不足时只描述；不得输出个人拒 offer 概率；
  不得基于学校 / 学历给淘汰建议；输出结构固定四段 + 数据限制。
- User：附摘要 JSON 与本地口径说明，要求引用 `metricId`。
- 提示词版本化并随报告与历史记录，便于回溯。

### 17.4 本地校验

发送前：字段白名单、身份字段零命中、`n<5` 全部抑制、互补抑制通过、体积与维度在预算内。
返回后：结构校验、Markdown 白名单清洗、数值一致性提示、敏感哨兵检索。

## 18. AI 安全、Key 管理与生产策略

### 18.1 开关与授权

- AI 功能**默认关闭**；开启需在设置中显式操作并阅读说明；
- 开关**不是**永久授权，每次发送仍需预览确认；
- 关闭 AI 不删除历史（清历史为独立操作），也不删除 Key（删 Key 为独立操作）；
- 开启 AI、保存 Key **不触发**任何网络探测（不探活、不查模型列表、不查余额）。

### 18.2 API Key 管理

- 输入框遮蔽显示，默认**仅存内存**（会话内有效）；
- 可选择加密保存，使用**独立 secret 记录**与独立生命周期，与招聘数据解密密钥分开；
- 锁仓时清空内存中的 Key；
- Key **不进**加密备份（普通备份排除 Key）、不进报告、不进日志、不进 URL、不进 `VITE_*` 环境变量；
- 删除 Key 不影响招聘数据；Key 许可按**端点**绑定，避免改端点后旧 Key 被转发；
- **不使用**真实 Key 作为测试 fixture，不提交仓库。

### 18.3 模型与参数

- 模型目录随版本打包，实施时按官方文档核实可用模型与参数，**不静默替换**；
- 旧模型（如已下线的 `deepseek-chat` / `deepseek-reasoner` 系列）标记兼容风险并提示；
- 参数：模型、思考模式、温度、`max_tokens`、超时；
- 不支持的参数在 UI 禁用，而不是发送后报错；
- 费用与等待时间在进行前提示。

### 18.4 网络与一次确认

- 唯一适配器；`POST {endpoint}/chat/completions`，`Authorization: Bearer <key>`，
  `stream=false`，`credentials: 'omit'`，`referrerPolicy: 'no-referrer'`，禁止重定向与缓存；
- 请求绑定 `hash / schemaVersion / endpoint / model / params / keyVersion`，确认 token **只能消费一次**；
- 按钮互斥防双击重复计费；`AbortController` 支持取消，超时后丢弃迟到结果；
- **不使用** `no-cors`、公共代理或网站 API 路由；
- 失败**不自动重试、不自动切换**；
- `TypeError` 只提示「网络或跨域可能失败」，**不硬判**为 CORS。

### 18.5 隐私级别

| 级别 | 内容 |
|---|---|
| strict | 仅总体 + 城市 + 状态结构；量化维度更粗分桶；HR / 岗位 / 学校层次全部省略；原因仅类别 |
| standard（默认） | 增加渠道、岗位类别、需求类型、画像层次、薪资 / 周期分桶、原因主题 |
| custom | 在 standard 白名单内增减**允许项**，**不能**解除身份禁出项 |

切换级别或修改配置后，旧预览**立即撤销**，必须重新生成。

### 18.6 生产安全策略

| 项 | 本地版 | 含可选 AI 版 |
|---|---|---|
| `connect-src` | `'none'` | 精确 `https://api.deepseek.com` |
| Service Worker | 仅缓存应用壳与静态资源 | 同左；**不**缓存、不排队、不重发 AI 请求 |
| 外部字体 / CDN / 统计 | 禁止 | 禁止 |
| 出站验证 | 断言零外部请求 | 断言仅确认正文发往白名单端点 |

- 生产构建需**实际验证**上述策略；GitHub Pages 的 meta CSP 不等价于响应头策略；
- 托管平台可达性（CORS）**不保证**；如遇跨域，仅提供自建独立代理说明，
  **不由网站运营方托管代理**，并提示代理可见 Key 与摘要；
- 自有代理配置属高级选项：改地址即撤销原授权，不转发旧 Key；
- 本仓库**不默认提供**代理程序代码。
