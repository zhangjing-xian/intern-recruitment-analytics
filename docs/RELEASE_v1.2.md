## 0. v1.2.1 修正了什么（2026-09-27，人工验收时发现）

用户在验收 v1.2.0 的报告导出页时发现「检查通过但四个导出按钮都点不动」。查下去是两个 bug，
都在**自动化从未覆盖到的那一半**（导出闸门的状态机）：

1. **闸门死锁**：`canExport` 要求 `confirmedFingerprint === fingerprint`，而唯一把它写成非空的地方
   在四个导出按钮自己的 `onClick` 里——那四个按钮偏偏 `disabled={!canExport}`。
   于是「不点按钮就无法确认，不确认就点不了按钮」，**导出功能永远不可用**。
   修正：「生成并查看预览」在生成预览的同时把它记为已查看（用 `next.fingerprint`，避免闭包旧值）；
   任何改结果的改动（脱敏级别 / 明细开关 / 筛选）都会让指纹变化、按钮自动回到禁用态，
   **「先看预览再导出」这条闸门没有被削弱**。
2. **哨兵误拦**：导出前的「本机已知敏感取值」检查把源列里**每一个非空取值**都当哨兵，
   于是受控字典词汇永远自撞——源里写推荐类型「内推」、报告里的渠道标签也是「内推」；
   源里写原因「薪酬」、报告里的原因类别也是「薪酬」→ 报告被判定「命中敏感值」并**阻断导出**。
   实测在演示数据（50 行合成样本）上命中 6 处、四个按钮全部锁死，而那几个字是**类别标签**，
   不是任何人的身份信息。修正：受控字典词汇（`内推` / `HR推` / 原因字典可命中的写法）不进哨兵集合；
   **具体人名**（如「示例推」）与**字典外的自由文本**照旧进——它们才是需要盯住的东西。
3. 顺带修掉一处**文案与事实不符**：预览过期时导出区顶部写的是「检查未通过」，
   而检查其实是通过的（用户看到的正是这个自相矛盾的页面）。现在四种「不能导出」的原因分开说：
   还没生成预览 / 预览已作废 / 检查未通过 / 这一份预览还没确认。

修正后的实测：`npm test` **1409 例 / 102 文件**（v1.2.0 是 1399/100，新增 3 例导出闸门交互 + 7 例哨兵收集）、
`npm run test:e2e` **10 例**（在真实 Chrome 里断言「预览前禁用 → 生成预览后可用」）、
`typecheck` / `lint` 全 0。
`_release/intern-recruitment-v1.2.0-ai.zip` 是修正前的归档，**已被 v1.2.1 取代**（两者都留在 `_release/`，
便于对照）；请以 **`intern-recruitment-v1.2.1-ai.zip`** 为准。

## 1. 这一版加了什么（用户的 4 条需求，全部按确认口径实现）

| # | 需求 | 实现要点 |
|---|---|---|
| ④ | 下钻之后能回到全局 | 分维度表、状态结构图、时间趋势图**三处**下钻旁边各有一个「返回全部数据」；它调用的就是筛选条那个「清空筛选」的**同一个纯函数**；没有筛选时置灰并说明原因 |
| ② | 推荐人是内推时渠道也算内推 | 新增清洗设置项（**默认关闭**，必须用户勾选）：只有**渠道为空或 `-`** 且推荐人 = 内推时才补成内推，来源标为「推断」、可撤销；渠道已有具体值时**绝不覆盖**，只标「渠道与推荐人不一致，请核对」；改它会换配置摘要 |
| ① | 清洗后的异常值可以改 | 清洗预览新增**异常行清单**（按严重度 / 问题类型筛选）+ 弹窗改值：填新值 + **必填原因** → 立刻按新值重新清洗（问题标记与统计跟着变）、可**撤销**；展开该行可看到**原值 / 自动清洗值 / 人工修正值 / 原因 / 时间**五栏；报告与导出注明「含 N 处人工修改」 |
| ③ | 多加图表 | 渠道、HR、需求类型、画像（毕业年级 / 学历 / 学校 / GPT 四张）、时间效率各补图；**拒 offer 专项页此前一张图都没有**，现有「拒绝原因分布」与「按维度的拒 offer 率 + 入职率」两张；导出侧 **PDF / 打印版带图**（图由本机从同一份脱敏报告重绘），Excel 仍只有数据表并在界面写明「要看图请用 PDF 或单独导出图片」 |

口径与理由（包括「为什么渠道补内推不能默认开启」「为什么人工修正必须绑定物理行号 + 表签名」）
逐条写在 `docs/DECISIONS.md`（**D-091** 人工修正、**D-092** 渠道补内推）与 `docs/PRD.md` 5.2。

## 5. 人工验收建议（针对本版新增的功能）

1. **返回按钮**：看板 →「分维度分析」任选一张表 → 点「只看该组」→ 表格旁的「返回全部数据」→ 确认 N 回到全量。
2. **渠道补内推**：清洗预览 → 「清洗口径确认」勾选「渠道缺失时按推荐人补成『内推』」→
   确认渠道为空 / `-` 的行变成「内推」并带「来源：推断」标记、渠道已写具体值的行**没变**并带「不一致，请核对」→ 取消勾选后完全还原。
3. **改异常值**：清洗预览 →「异常行清单」→ 点「修改这一格」→ 留空原因保存（应被挡住）→
   填原因保存（值变了、原问题标记消失、出现「已人工修改」与撤销）→ 点撤销回到原值；
   导出 Excel / Markdown 时确认报告里注明「含 N 处人工修改」。
4. **图表**：看板往下滚（渠道 / HR / 需求类型 / 画像 / 时间效率都有图，点柱子可下钻）→
   拒 offer 专项页（原因分布 + 率对比）→ 报告导出页点「打印 / 另存为 PDF」，确认新窗口里**带图**，
   再另存为 PDF 看排版。
