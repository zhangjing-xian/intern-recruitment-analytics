# IMPLEMENTATION_PLAN.md — 实施计划与分步提示词

> 本文件把需求文档第二部分（分步开发提示词）整理为可执行的实施计划：
> 每步的目标、依赖、输入、产出、完成标准（验收）与注意事项。
> 执行每一步前必须先读 `AGENTS.md` 与 `docs/PRD.md`。
> 规则：**一次只做一步**，每步结束汇报「实际运行了什么 / 未运行什么 / 被阻塞什么」，
> 不把「计划测试」写成「测试通过」。

## 1. 执行顺序与依赖

```
步骤0  项目契约与实施计划（本步骤，仅文档）
  └─ 步骤1  初始化 React + Vite + TS + Tailwind，页面壳与路由
       └─ 步骤2  字段、类型、枚举与映射配置（数据契约）
            └─ 步骤3  Excel / CSV / 粘贴解析 → RawRow
                 └─ 步骤4  字段识别与手动映射
                      └─ 步骤5  清洗、校验、重复确认与预览
                           ├─ 步骤6  IndexedDB 加密本地仓（临时模式 / 解锁 / 锁定 / 改密）
                           │    └─ 步骤7  派生指标与分析引擎（纯函数）
                           │         └─ 步骤8  总览看板与全局筛选
                           │              ├─ 步骤9  城市 / 渠道 / HR / 岗位 / 画像分析
                           │              └─ 步骤10 拒 offer 专项与本地结论
                           ├─ 步骤11 报告脱敏与 PDF / Excel / 图片导出
                           └─ 步骤12 设置、名单、备份与彻底清除
AI-1 → AI-2 → AI-3 → AI-4 → AI-5 → AI-6 → AI-7   （AI 支路，需本地主链路可用）
  └─ 步骤13 PWA、静态部署配置与 README
       └─ 步骤14 测试、隐私核验与最终验收
            └─ 步骤15 清洗预览的异常行清单与逐格手动修正（**已随 v1.2.0 交付**）
                 └─ 步骤16 图表补齐 + 导出带图（**已随 v1.2.0 交付，v1.3.0 完成看图反馈的第三轮**）
```

顺序说明（来自需求文档）：

- 新开发顺序：**原步骤 0–12 → AI-1 至 AI-7 → 修订后的步骤13–14**。
- **步骤14 之后先做发布前人工验收**：用户当时的结论是「先把 v1.1 交付，再继续改」，
  因此 15 / 16 是在 v1.1.0 归档冻结之后开工的，并作为 v1.2.0（含 v1.2.1 修正）与 v1.3.0 交付。
  它们改了清洗层与配置摘要，所以**步骤14 的验收证据已按新版本重跑**（见 `docs/ACCEPTANCE.md` §0）。
- 若已有网站：先执行「契约迁移」提示词，再执行 AI-1…AI-7，最后重跑步骤13–14 的相关验证。
- AI-1 先用**合成聚合 fixture** 把脱敏与预览做出来，AI-2 再接真实摘要生成器。
- PWA 可以提前，但**不得**因 PWA 拖延加密或脱敏验收。

## 步骤6：实现 IndexedDB 加密本地仓

```text

注意事项：默认禁止明文持久化；不保存密码 Hash 来代替数据加密；不承诺密码找回或绝对内存擦除；

```
