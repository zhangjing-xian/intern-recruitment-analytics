### 1. 【修改】项目概述

建立可反复使用的实习生招聘复盘工具，服务上海、广州、杭州日常招聘。用户粘贴 Excel 区域或选择本地 XLSX/CSV，经映射、清洗和确认后，在浏览器本地得到统计、对比、规则化结论及脱敏报告。

产品定位：面向 offer 名单的经营分析工具。输入没有简历投递、面试、成本等完整链路，不能称为完整招聘漏斗平台，也不能计算全链路招聘转化率、渠道ROI或完整人效。

核心价值：减少重复整理；统一分母和清洗规则；给出可追溯的运营线索；默认在用户浏览器内处理数据。本地自动结论继续使用确定性规则及模板；【新增】可选AI深度分析仅在主动点击、脱敏预览并确认后，将聚合摘要直发DeepSeek，详见16–20章。

成功标准：同一数据、同一配置得到一致结果；用户能看懂每个指标的分母；本地导入/分析/导出不传输招聘数据；AI只发送本次明确确认的脱敏聚合摘要；本地结论可追溯，AI结论另标生成来源与待核验状态。

### 2. 用户角色与使用场景

| 角色 | 使用场景 | 权限与边界 |
|---|---|---|
| 招聘HR | 每周导入、查看渠道/需求/拒offer问题 | 管理当前浏览器本地数据仓 |
| 招聘负责人 | 在自己的浏览器导入本人持有的数据或阅读脱敏报告 | 无远程查看他人浏览器能力 |
| 网站维护者 | 发布静态代码、维护规则说明 | 不设置数据管理后台；不接收业务数据 |

“所有人可用、各看各的数据”在本方案中指不同设备/浏览器配置文件各自保存数据，不是云端账号权限系统。相同浏览器配置文件和相同站点来源会共享存储；本地仓密码可以提供静态加密保护，但不等于操作系统账号隔离。共享电脑优先使用独立系统账号/浏览器配置文件；可提供不同加密仓，但不得用选择一个HR名称冒充身份认证。

典型流程：打开网站→选择临时分析或解锁本地仓→导入→映射→确认清洗及去重→看板筛选→拒offer排查→预览脱敏报告→下载→锁定或清除。

### 3. 功能范围与非功能范围

#### 3.1 功能范围

1. 粘贴TSV表格、上传XLSX/CSV、工作表选择、编码和分隔符预览。
2. 标准表头模板、字段自动建议和手动映射、本地映射模板。
3. 类型/枚举/日期清洗、重复确认、错误定位、有效样本说明、可撤销重算。
4. 数据集替换、新建快照、谨慎追加；数据集版本和配置版本保留。
5. 全局筛选、总览、城市、渠道/推荐人、HR、岗位/序列/部门、需求类型、画像、薪酬房补、时间效率。
6. 拒offer专项、组间对比、原因缺失分布、可解释风险组合、本地自动结论。
7. PDF（本地打印保存）、XLSX、PNG导出；统一脱敏层。
8. 本地加密、锁定、名单与规则管理、一键清除、加密备份恢复。
9. 静态部署；PWA离线应用壳可作为后续增强。
10. 【新增】可选DeepSeek深度分析：摘要生成、严格脱敏、完整预览、浏览器请求、结果复制/导出/加密历史。

#### 3.2 非功能要求

- 【修改】安全：默认本地模式无业务出站；AI唯一例外是用户确认后的白名单聚合请求。不加载第三方运行时脚本/字体，不含埋点/广告/遥测/错误上报；AI文本安全渲染。
- 性能验收基准：桌面Chrome/Edge、4核CPU/8GB内存、10,000行×21列合成数据；解析+清洗目标≤5秒，筛选聚合目标≤500ms（预热后）；记录实际机型和测量方式，不把目标宣称为已达成。
- 默认文件限制20MiB、50,000行，均可配置；解析后也检查解压后大小/单元格数；超限阻止或提示拆分，不让浏览器卡死。
- 可用性：中文界面；≥1280px桌面为主要布局；键盘可操作、焦点可见、颜色外还有文字、图表配表格；手机可浏览概要。
- 正确性：统一指标引擎；小数只在展示层舍入；缺失≠0；空分母显示“—”。
- 可靠性：取消导入不改现有数据；存储失败不报保存成功；迁移失败可回退；导出失败可重试。
- 可维护性：TypeScript严格模式、领域纯函数、版本化口径、依赖锁文件、单元/集成/端到端测试。

#### 3.3 明确不做

云账号、在线协作、共享数据库、网站数据上传接口、未经逐次确认的云AI、自动联网补学校信息、跨设备自动同步、第三方统计、服务器报告生成、根据风险标签自动淘汰候选人、以单一拒offer率自动给HR绩效排序。

#### 4.3 字段映射机制

“学历/学位”“推荐人/招聘HR”“入职时间/offer接受时间”不能互相自动映射。两个源列竞争一个目标字段时必须选择或显式合并规则；不静默覆盖。多余列默认忽略，不能意外导出；可映射到已定义的扩展字段。模板保存源表头签名、字段映射、枚举/单位规则和版本，不存示例候选人数据。

### 5. 数据清洗、导入和重复处理

#### 5.1 解析与类型

- 上传指浏览器读取本地File，不创建网络上传；粘贴仅通过输入框/明确粘贴动作，不后台读取剪贴板。
- XLSX显示工作表、可见/隐藏状态和行列数，用户选择表及表头行；默认第一行，空行跳过并计数；隐藏行/列不默默排除，显示是否包含选项。
- XLSX只读值和已有缓存结果，不执行宏、公式、外部链接，不联网更新。关键列公式无缓存时提示转值后重传；有缓存也标记可能陈旧。
- CSV默认UTF-8，允许用户选择GB18030等受支持编码；正确处理BOM、引号、逗号、制表符、字段内换行；粘贴TSV同样尊重带引号内容。
- 数字字段不使用隐式JavaScript转换；空白、-、N/A按配置视为null，负薪资/无穷值报字段错误；工资带范围时保留原文并要求确认，不擅取中点。
- 清理首尾空白和不必要换行；学校、岗位等语义不相同的文本不做激进合并，岗位项目代号不能自动删除。

#### 5.2 日期

- Excel读取工作簿1900/1904系统；仅日期列转换数字序列，需求ID绝不转换日期；1900系统异常序列60按无效日期提示。
- 支持明确YYYY-MM-DD、YYYY/MM/DD、YYYY年M月D日及合法Excel日期。01/02/2026等歧义要求确认日月顺序；不凭系统区域猜测。
- 统一为无时区日期字符串，以日历日序号相减，避免夏令时/UTC转换少一天；同日为0天。
- 入职早于启动、预计离职早于入职为错误；保留行进入计数，但排除受影响周期，显示错误数。
- 分析截止日dataAsOf由用户确认，默认导入当日；“已入职”但入职日晚于截止日标记矛盾，不自动改状态，周期排除至确认；其他状态未来计划入职正常。
- 超长周期默认>180天提示核实，不自动截尾或删除；若有效仍参与周期，并展示中位数/P75和异常数。

#### 5.3 状态与单位

- 状态按明确字典统一：已送审批→offer审批中；“审批通过”不等于候选人接受；离职、撤回、取消等进入其他并保留原值，除非用户明确定义另一个口径版本。
- 薪资导入页必须确认币种及周期，建议选项“人民币元/月”“人民币元/天”“其他”“暂不确定”；暂不确定时只展示未确认原值概况，禁用待遇对比及低薪风险标签。
- 混合月薪/日薪不得直接聚合；未提供计薪天数和明确换算规则不换算。每条记录保留单位，分别展示。
- GPT字段以原值优先，缺失可用本地名单匹配；不在名单只有当用户声明名单完整且采用“名单模式”时才判否，否则仍未知。冲突要展示，两种来源都保留。

#### 5.4 重复、替换和追加

- 原始完全重复与清洗后疑似重复分别展示。完整相同记录默认建议“每组保留首条”，必须确认后生效；原始数据和去重决策可回溯。
- 不用需求ID单独去重；同需求多个候选人是合法的。同姓名也不能认定同一个人。
- 缺少offer唯一ID时，需求ID+姓名+启动日期只可作为疑似键，不作为自动合并主键。
- 新导入默认“新建快照”或明确“替换当前数据集”，不自动累计历史文件；同一历史名单反复导入不会自动让总数增长。
- 追加模式先展示重复与状态冲突。无稳定offerId时不自动把已审批、待入职、已入职合并为同一offer；让用户决定保留/替换/另建快照。
- 每次提交为事务：解析预览、确认、生成新版本、成功后切换；失败不破坏旧版本。

#### 5.5 质量分级

阻断：文件无法解析、无数据、缺offer状态映射、目标列冲突、超限。字段错误：非法日期/薪资，仅排除对应指标；警告：未知枚举、缺失、超长周期、疑似重复、计划日期语义。质量页显示原始行数、空行数、保留行数、去重行数、异常行数、各指标有效样本数，支持按问题过滤并定位原始行号。

### 6. 指标口径与计算公式

#### 6.1 统计粒度和分母

默认一行代表一次offer相关记录，不代表唯一候选人或完整需求。审批中也在名单中，因此总卡片命名“总offer记录数（含审批中）”，提示不等于正式发放offer数。

当前数据集、筛选条件和去重策略下：N=所有保留记录；J=已入职；P=待入职；A=offer审批中；R1=拒绝offer；R2=拒绝口头offer；R=R1+R2；U=其他/未知；D=J+P+R。始终满足N=J+P+A+R1+R2+U。

| 指标 | 公式/规则 | 展示说明 |
|---|---|---|
| 是否接受offer | 状态∈{已入职,待入职} | 派生布尔；未知状态为null |
| 是否拒offer | 状态∈{拒绝offer,拒绝口头offer} | 派生布尔；未知状态为null |
| 接受数、接受率 | J+P；(J+P)/D | 接受不等于实际入职 |
| 拒offer率 | R/D | D排除审批中、其他和未知 |
| 入职率 | J/D | 不使用J/N冒充此指标 |
| 待入职占比 | P/D | 默认采用核心率分母；另可显示P/N并明确“占全部记录” |
| 审批中占比 | A/N | 明示分母不同 |
| 状态结构占比 | 各状态数/N | 用于状态图；含其他/未知 |
| 名单覆盖需求数 | countDistinct(非空需求ID) | HR内按本HR记录去重；跨HR相加可能超过全局 |
| 招聘周期天 | 入职日期−启动日期 | 日历日，不是工作日；日期合法且非负 |
| 平均实际招聘周期 | Σ合法周期/有效已入职样本数 | 默认仅J，显示有效n和排除数 |
| 待入职计划周期 | P中合法日期差的均值/中位数 | 单独显示，不能混入实际周期 |
| 预计实习天数（可选） | 预计离职−入职 | 仅计划，不能称实际留存 |
| 原因填写率 | 有有效原因的拒offer数/R | 非拒offer不入分母 |

N或D或相关有效n为0时，显示“—/无有效样本”，不显示0%。图表需要保留计数为0的状态。平均数/金额展示两位小数，人数整数，率两位小数；内部保留完整精度。汇总率必须合计分子分母再相除，不能平均各城市百分比。

#### 6.2 同岗薪酬基准

严格同组：城市+序列+规范化岗位+币种+计薪周期。参照集合默认是当前数据集及时间范围中的全部保留状态记录、有效薪资；不受渠道/HR/offer状态/薪资筛选影响，避免切换“拒offer组”导致基准漂移。参照集合定义和版本显示在图旁；业务筛选影响展示对象，不静默改变基准。若用户切换基准范围必须显式记录。

- 默认参照有效样本n≥5才出基准；n<5显示“同岗样本不足”，不打低薪标签；不自动扩展到不同岗位。以后可选择同城市同序列回退，但必须标记回退层级。
- Q(p)用线性插值：排序x0…x(n−1)，h=(n−1)p，j=floor(h)，Q=xj+(h−j)×(x[min(j+1,n−1)]−xj)。P25/P50/P75由此计算。
- 薪资分位排名采用并列中位秩：[小于该薪资数+0.5×等于该薪资数]/n×100%；与分位数值是两个概念。
- 低于中位数=salary<P50；相等不标低。样本含自身，这是描述性定位，非独立预测。
- “薪资+现金房补”仅在同币种同周期且金额明确时计算；住宿不折算成现金。房补缺失时总额未知，不能填0。

#### 6.3 分层维度和全局筛选

城市、渠道、推荐类型、HR、岗位、序列、部门、需求类型、毕业年级、学历、学校、GPT、薪资区间、房补类型均复用相同聚合函数：N/J/P/A/R/D、入职率、拒offer率、有效周期n和均值。

不同字段间AND，同字段多选OR；未选择某字段等于不过滤，未知是可选的独立值。状态筛选会改变D，应明确提示“当前子集率”；专项比较默认采用未加单组状态筛选的当前人群，若已有单组筛选，提示切换，不暗中清除。

时间默认不筛选；用户选择时默认按启动招聘日期，可切换入职日期，并显示选中基准。日期缺失数单列、提供纳入未知选项。没有offer发出日期不能显示“本月发offer趋势”；按入职日期筛选也不能称发offer批次表现。dataAsOf是数据快照声明，不能仅凭当前状态还原历史某日状态。

### 9. 拒offer专项分析设计

#### 9.1 分析人群

拒offer组=拒绝offer+拒绝口头offer；入职组=已入职。待入职与审批中不进入这两组比较，但待入职依用户定义仍在拒offer率分母D中。页面必须明确“组间比较人群”和“核心率人群”不同。

对每个维度同时给出两种视角：

1. 组内构成：某特征在拒offer组的记录数/R，对比该特征在入职组的记录数/J；这是画像构成，不能称该特征拒offer率。
2. 特征内结果：该特征拒offer数/该特征D，同时展示入职率、待入职数和样本量。

比较维度：渠道、推荐类型、HR、岗位、序列、部门、需求类型、年级、学历、学校、GPT、薪资、房补。数值用有效n、中位数、P25/P75及分布；类别用计数、比例和百分点差。薪资对比在同城市/序列/岗位/单位内优先展示，混合总体仅描述。

#### 9.2 原因分析

默认一行一个主要原因：薪酬、住房/住宿、其他offer、岗位内容、地点、实习时间、学业安排、个人原因、其他、未填写。可维护字典但不凭候选人背景推断原因。多原因扩展需明确主因或多选统计，不能混用分母。

饼/条形图以全部拒offer记录R为分母，包含“未填写”；可另提供已填写原因分布并标明有效n。【修改】当前新附件7条拒offer的原因全缺失，应显示原因填写率0%，本地与AI都不得输出“主要因为薪资”。

#### 9.3 风险标签与组合

名称建议为“拒offer运营关注标签”，页面解释这是规则筛查，不是个人概率模型，不用于自动淘汰或歧视候选人。GPT、学校、学历仅作聚合复盘特征，不单独触发个人高风险。

基础条件：GPT为是；房补类型明确为无补贴；同岗有效薪资低于P50；招聘等待超阈值。未知条件保持unknown，不当false或零补贴。

时间条件必须区分：已入职实际周期>30天可用于事后描述；待入职/审批中截至日−启动日>30天叫“当前等待时长”；拒offer因缺少拒绝日期，历史等待标签为未知。不能用入职后的结果作为预测特征，也不能把当前等待算成历史拒offer周期。

可配置组合示例：GPT+无补贴+低于同岗P50；无补贴+低薪；低薪+当前等待>30天。阈值30天仅为初始运营规则，用户可改，并随报告记录。提供住宿不命中无补贴条件。

历史组合结论门槛：组内D≥10、拒offer≥3，且组内拒offer率比同基准总体高≥10个百分点，才输出“观察到较高拒offer关联”；否则只显示描述或样本不足。只在可比较状态均可观察的特征上评估组合，不将缺失时间字段当未超时。多个组合探索产生的线索不是显著性检验。

每条风险输出包含：规则ID/版本、命中条件、未知条件、命中记录数、有效D/R、比较基准、率差、适用范围、建议核查事项。禁止输出“此人拒offer概率80%”等未经训练和校准的概率。

#### 9.4 行动建议

规则化建议映射：原因缺失→补充拒绝访谈；同岗低薪关联→核查报价与同岗基准；无补贴关联→核查住宿需求与补贴资格；审批记录较多→梳理审批节点；等待过长→跟进当前节点；小样本→继续采集。不得把学校标签直接转成“不招聘该类学校”。

### 10. 【修改】数据安全与隐私方案

#### 10.1 安全承诺及边界

【修改】默认招聘文件、清洗、统计和报告在浏览器内完成。新增AI仅在主动点击并确认完整脱敏预览后，浏览器把聚合摘要及认证Key发往DeepSeek；不发原始明细、不经网站服务器、不做远程日志。Key本地管理，认证时发送给DeepSeek，不等于绝不离开设备。静态服务器仍接收加载资源所需的IP等元数据。自有代理如启用也是独立接收方；不得承诺绝对匿名、供应商零保留或本地清除能撤回已发内容。完整隐私文案见第20章。

IndexedDB按来源隔离，不能把同一来源的不同URL路径当作安全隔离。GitHub Pages同账号不同项目通常共享来源，应优先独立域名/来源，避免与不可信应用同源。加密可保护落盘数据，但不能防止解锁时的恶意扩展、XSS、已被控制的设备或篡改后的站点代码。

#### 10.2 两种本地存储模式（AI开关独立）

- 临时模式：默认可直接分析，只在内存，刷新/关闭即丢失；不自动写入业务数据。
- 加密本地仓：用户设置密码后持久化；生产版不提供默认明文落盘。密码不可找回，先提示可下载加密备份；新浏览器无法自动读取旧浏览器数据。

【新增】AI默认关闭。临时模式Key只在内存；选择持久化Key或保存AI历史必须使用加密仓，不能为了新功能降低原加密要求。

#### 10.3 加密设计

使用Web Crypto API：PBKDF2-HMAC-SHA-256由密码派生AES-GCM 256位密钥；随机salt至少16字节，每次加密生成独立12字节IV，禁止同密钥复用IV；128位认证标签。PBKDF2迭代次数做本机基准并持久化，初始建议600,000次并测试可用性，该值是本方案初始配置而非永久安全保证。

加密信封存储formatVersion、schemaVersion、kdf参数、salt、iv、ciphertext及最小非敏感随机标识。候选人数据、原始预览、HR/岗位、文件名、清洗记录、分析缓存与敏感自定义规则均在密文中；不对明文姓名/薪资建立IndexedDB索引。AES-GCM附加认证数据绑定仓ID和版本，防止信封错配。

密钥不可导出且只驻留内存，不保存密码或解锁密钥到localStorage/IndexedDB。【新增】API Key仅可加密存储，不能与解密密钥一并落盘；历史不得包含认证头。解锁后内存计算；手动锁定、刷新、默认闲置15分钟锁定。锁定时清空可控状态和图表缓存、撤销Blob URL；JavaScript无法保证物理内存取证级擦除，不能夸大。

密码错误/密文被修改均以解锁失败处理，不输出原始敏感内容。改密：先校验旧密码，生成新salt和密钥，重新加密并事务替换，失败保留旧仓；禁止部分数据用新密码、部分用旧密码。敏感持久化状态更新也必须使用新IV。

#### 10.4 出站控制和前端防护

- 所有依赖、图标、字体、图表、Worker脚本打包同源；禁止CDN脚本、在线字体、在线图片、地图、远程错误上报。
- 用户输入通过React文本渲染，不使用dangerouslySetInnerHTML；不执行表格公式、不激活原始单元格链接；CSV/XLSX导出防公式注入。
- 生产CSP原则：default-src 'self'；script-src 'self'；connect-src 'none'（仅本地版）；【修改】含可选AI版精确允许https://api.deepseek.com，仍须应用层逐次确认，详见18.6；object-src 'none'；base-uri 'none'；form-action 'none'；img-src仅self/blob/data；Worker仅self；外部字体禁用。样式若图表确需内联需单独限定style策略，不放开script的unsafe-inline/eval。
- PWA预缓存可能需要读取同源静态资源，须单独设计Service Worker请求策略与CSP；若PWA必须额外允许connect-src self，要限定静态路径及无数据载荷，并用网络测试验证。不得为PWA一键放开所有网络。
- 能配置响应头的平台使用响应头CSP及frame-ancestors 'none'；GitHub Pages的meta CSP有能力限制，不能声称提供完全等价响应头保护。
- 无第三方统计，包括托管平台的可选Web Analytics/Insights；构建/CI只处理合成数据和代码，不包含真实招聘附件、密码、真实截图或备份。

#### 10.5 本地备份、清除及存储边界

浏览器可能回收存储，用户清理站点数据/无痕窗口退出也可能丢失。显示容量与持久存储申请结果，不承诺永久保留；提供本地加密备份和导入恢复，不能把备份上传到站点。

一键清除以明确确认弹窗列出影响：当前应用全部本地仓、原始/清洗数据、映射、学校名单、分析缓存、偏好、IndexedDB、应用自己的localStorage、Cache Storage和Service Worker。先通知并关闭其他标签页连接，再删除；被占用则提示关闭标签并重试。只清本应用命名空间，不删除同源其他应用。内存及Blob URL同时清理，页面回到空状态。无法删除用户已下载的报告/备份，应明确告知。【新增】清全部包含加密Key、AI历史与在途任务；单独清AI历史不删招聘源数据或Key；清除后忽略迟到响应，且不能撤回DeepSeek已接收内容。

#### 10.6 报告默认脱敏

- 默认导出聚合报告，不导出逐条明细。需要明细时姓名替换为报告内候选人ID；没有可靠人员ID时实际是记录级代号，避免声称跨批次是同一人。
- 薪资固定区间默认为<3000、[3000,4000)、[4000,5000)、[5000,6000)、≥6000，仅针对确认人民币元/月；其他单位使用独立配置。准确中位数等在外发报告也改为区间或隐藏，避免间接恢复原值。
- 同时默认隐藏需求ID、具体推荐人、自由文本原因和原始行数据；HR用HR代号；学校/岗位小组n<5合并或抑制，防交叉识别。必要时做互补抑制，避免用总计减去其他组还原小组。
- 自由文本原因不能只替换姓名就直接导出，默认仅导出标准原因分类。公司部门/岗位是否保留可由用户在预览选择。
- 同一导出文件内代号稳定，跨报告默认重建；对照表不导出。脱敏是降低暴露，不承诺不可重新识别。
- 导出前先构造唯一SanitizedReport模型，所有格式从该模型生成，不允许PNG截图原始页面或XLSX隐藏sheet保留原文。tooltip、图注、文件名、PDF元信息、导出日志同样不包含敏感字段。
- 报告下载后由用户控制，站点加密不等于导出文件已加密；默认不提供“一键原始数据报告”，加密备份与脱敏报告是不同入口。

### 11. 【修改】技术架构建议

推荐React+Vite+TypeScript严格模式+Tailwind CSS；图表统一选ECharts（适合多维分析与分位图），不要同时引入两个图表框架。SheetJS解析XLSX，PapaParse处理CSV/TSV，Dexie封装IndexedDB，Web Crypto加密，Vitest+Testing Library+Playwright验证。

依赖安装时核实官方版本与安全公告，记录锁文件和来源，不在本需求中硬编码“最新版本”。尤其SheetJS按其官方分发说明选择来源，再打包到本地；不能照搬旧博客的包版本或运行时CDN引用。

分层：导入适配器→原始数据→映射/清洗/质量报告→确认后的领域记录→统一筛选/聚合/统计→图表和本地结论→脱敏报告→本地文件。持久化通过加密仓接口单独接入，不让组件直接调用IndexedDB。

【新增】AI支路：聚合引擎→AnalysisSummary→AI脱敏引擎→SanitizedAiPayload→完整预览/一次性确认→固定network adapter→DeepSeek→响应校验/Markdown净化→本地展示/加密历史/脱敏导出。只有网络适配器能发AI请求，且不能接收原始记录类型。增加ai/summary、ai/consent、ai/client、ai/history职责模块；不新增网站服务器。

建议目录职责：domain（字段/口径纯函数）、importers、cleaning、analytics、insights、storage、crypto、privacy、exporters、workers、features、components、tests、docs。只规划职责，不要求过度抽象。

所有长任务（解析/聚合/加密可按需要）在同源Web Worker运行；消息带任务ID，支持取消、过时结果丢弃和错误传播。UI只显示进度，不能把所有记录打印进控制台。

版本：数据schema、字段模板、学校名单、计算规则、脱敏规则分别记录；更新名单/别名时展示重算影响并生成新分析版本，已有导出快照不被修改。

导出：XLSX仅写安全值与口径页；PNG从脱敏图表离屏渲染；PDF优先专用打印版+浏览器“另存为PDF”，在页面明确需要本地打印对话框。后续可用本地PDF库实现自动下载，但必须解决中文字体与分页，不引入远程转换服务。

部署：Vite构建dist静态目录；GitHub Pages设置正确base；为兼容静态刷新用HashRouter，或在支持平台配置回退。Cloudflare Pages/Vercel只启用静态托管，不创建Functions/API Routes/Worker业务后端。三个平台任选其一，不要求同时上线。依赖联网下载发生在开发构建阶段，与用户运行时招聘数据处理区分。

#### 12.1 附件核对验收

### 16. 【新增】AI深度分析模块

#### 16.1 目标及不可突破的边界

在既有本地分析完成后，用户可选择让DeepSeek解释脱敏聚合结果。默认AI关闭；开关、保存Key、导入文件、切换筛选、打开历史均不触发任何DeepSeek请求。只有从看板点击“AI深度分析”，查看本次完整脱敏预览并确认，才允许发起本次调用。

网站仍为静态前端，无网站业务后端。新增的是经授权的浏览器外部API调用，不再承诺“所有模式的数据绝不离开浏览器”。原始数据、身份对应表、Key的本地副本和历史仍只在本地；DeepSeek会收到本次脱敏聚合请求及用于认证的Key，也可能处理IP等网络信息。不能把“Key只存本地”写成“Key绝不离开浏览器”，因为Authorization认证必然把Key发送给DeepSeek。

本模块不允许上传文件、图片、原始行、候选人列表、候选人ID列表、单个需求记录、HR姓名或学校原名；更换脱敏级别也不得绕过。即使把姓名改为候选人ID，逐行数据仍是明细，不能发送。需求-001等代号仅供本地报告使用；AI摘要只发送需求数量，不发送逐需求统计。

#### 16.2 用户流程及状态机

1. 看板右上角显示“AI深度分析”；无有效本地结果时禁用，说明原因。AI未启用或无Key时引导设置，保存后仍须重新点击并确认，不自动续发。
2. 冻结当前数据版本、去重策略、筛选快照与统计口径，在本地生成AnalysisSummary。
3. 经过第17章AI专用脱敏、稀疏单元抑制、结构白名单校验，得到SanitizedAiPayload和脱敏说明。
4. 打开“脱敏预览”：展示业务JSON、系统提示词、最终messages及model/有效参数、目的域名/完整路径、直连或代理、脱敏级别、移除/合并项目、内容大小、token粗估及可能产生费用。Key始终遮蔽，不进入预览、复制内容或请求正文。
5. 预览中的最终请求正文可完整展开、复制；不允许只展示摘要却发送额外隐藏数据。用户只能修改配置/选择模块后重新生成，不能直接编辑JSON绕过校验。
6. 点击“确认并调用DeepSeek”后，冻结正文并生成一次性本地授权记录，绑定正文hash、数据/筛选/规则版本、目的地址、模型/参数与Key槽位版本。请求层发送已预览的同一序列化正文，不重新查询实时看板。
7. 正在请求时禁用重复提交，提供取消；成功进入结果页。取消、超时、失败不自动重试，不切换模型/代理；“重新分析/重试”须重新预览确认。
8. 返回Markdown以安全组件展示：核心结论、可能原因、风险预警、行动建议，附证据和限制。支持复制、导出、显式“保存到本地历史”。

状态：未启用→待分析→生成摘要→待确认→发送中→成功/失败/已取消。关闭预览即作废授权；数据、筛选、隐私级别、自由文本摘要、模型、参数、提示词、Key或地址变更均作废旧预览。切换数据集/锁仓/清除历史时中止在途请求并提升任务版本，迟到响应不得重新写入。

本地hash只用于防止误用旧预览，不是匿名化证明或对恶意脚本的安全沙箱。不做“记住本次同意，下次自动发送”。

#### 16.3 分析摘要JSON契约

摘要只包含聚合统计与派生指标。建立严格版本化JSON Schema，所有对象关闭未知属性；网络适配器只能接收通过校验且已确认的SanitizedAiRequest，不能接收NormalizedRecord[]。不用原始对象展开、JSON.stringify全量store或删除黑名单字段的方式凑摘要。


#### 16.5 本地结果、历史和导出

结果页显示请求模型及返回模型（可能是别名解析结果）、分析时间、脱敏级别/规则版本、提示词版本、范围、状态、usage（如有）、本次已发送摘要。时间可以保存在本地结果元数据，不回传下一次请求。

显示message.content；不把reasoning_content当最终报告，不默认保存或导出内部推理文本。无content或finish_reason为length等异常时显示“不完整”，不得标成完整成功或自动续写。

Markdown禁用原始HTML、脚本、iframe、远程图片和嵌入；默认外链渲染为文本，防止模型用链接把数据再次带出。复制使用净化后的Markdown；导出复用本地脱敏报告流程，提供Markdown、打印PDF，并可把AI章节纳入现有XLSX/PNG报告。内容来自模型也视为不可信文本，再做本地敏感字段检查与导出预览；保留HR代号，不反向还原姓名。

历史只在用户点击保存后写入加密仓，包括脱敏请求、净化结果、上述元数据；绝不保存Authorization、Key或完整HTTP日志。临时模式关闭页面即丢失，保存历史须先建立加密仓。普通备份默认排除Key，可包含加密AI历史。支持删除单条和“清除AI分析历史”，操作不删除招聘源数据或Key；“清除全部本地数据”则删除三者。关闭AI开关不自动删除已存Key/历史，界面说明并提供独立删除按钮。

本地清除不能撤回已经发给DeepSeek的内容，不能宣称删除供应商端记录；发送取消也不能保证供应商停止处理或免除已产生费用。

### 17. 【新增】AI脱敏引擎设计

#### 17.1 与原报告脱敏的关系

复用原privacy模块中的文本标准化、区间、别名与抑制函数，但保留两个独立契约：SanitizedReport允许用户选择本地明细；SanitizedAiPayload永远只允许聚合。禁止把报告模型直接传给网络层。

流水线：本地指标引擎→候选聚合摘要→白名单字段重建→身份删除/标签映射/数值分桶→跨表稀疏性及可反算检查→Schema+敏感字符串兜底检查→完整预览→一次性确认→固定请求。扫描是兜底，不能代替白名单或保证识别全部个人信息。

#### 17.2 脱敏级别

| 规则 | 严格（默认） | 标准 | 自定义 |
|---|---|---|---|
| 原始行、候选人/需求ID、HR原名、学校原名、原始薪资、完整日期 | 全部禁止 | 同样禁止 | 同样禁止，不能关闭 |
| 最小单元人数k | 5 | 5 | ≥5，可提高 |
| 交叉分组维数 | 默认最多2；不足时降维 | 最多2 | 可减少，不可任意生成高维明细 |
| 薪资/周期 | 默认固定粗桶 | 可选经校验桶，不能窄到近似单值 | 配置边界，仍过k和单位检查 |
| 部门/岗位/序列 | 按用户要求默认保留经检查的标签；小群体时合并/类别化 | 同左 | 可强制映射为业务类别 |
| 拒绝原因说明 | 关闭 | 关闭 | 可开启“本地主题归并”，二次确认；禁止逐条原文 |

“严格”意味着身份字段禁出、只聚合、稀疏抑制和完整确认，不代表保留的部门/岗位名称毫无商业敏感性；预览要专门提醒这些标签默认保留，可改为类别。三个级别的区别是信息粒度和可配置程度，不能把“标准”设计为允许发送原始数据。

| 原始字段 | AI发送规则 | 说明 |

| 需求ID | 删除；只保留安全的覆盖需求总数 | 需求-001映射可在本地用，不放进AI摘要 |
| 招聘HR | HR-A、HR-B等请求内代号 | 每次请求重建；不发反查表；聚合仍要k检查 |
| 城市 | 上海/广州/杭州/其他/未知 | 原始园区/地址不发送 |

#### 17.4 稀疏数据与再识别检查

k默认5是本产品门槛，不是匿名化保证。按分组人数≥5还不够：分组内拒offer、入职等结果单元若在1至k−1，隐藏该单元以及可反推它的率/互补量。零值仅在不破坏其他隐藏单元时可发。必要时合并类别、降低维度，无法安全发布则移除整张表。

例：某渠道D=10、拒offer=1，即使总人数≥5，也不能发送拒绝率10%；该率可以还原1人。若总计和其余城市会反推出被隐藏城市，需互补抑制；同一请求中的总体、城市、HR、交叉表一起检查，不能每张表各自“过关”后拼接。

精确安全检查难以支持任意重叠交叉查询，MVP仅允许预定义表集合。首次发送前冻结完整发布快照；同一数据集版本后续换筛选若不能证明联合已发送摘要仍安全，阻止增量细分、建议沿用上次范围或更粗汇总。发送账本只存加密本地元数据和已发布摘要，不记录Key；清除历史后无法完整检查跨次组合，提示该限制并仍执行单次检查，不声称可防所有跨次推断。将来可引入更严格的发布预算或差分隐私，但本期不冒称已实现。

对于小样本数据，严格模式可能只剩少量总体指标；显示被抑制原因，不降低门槛凑“深度分析”。如无安全可分析摘要，禁用发送并建议扩大本地分析范围。

#### 17.5 拒绝原因说明的二次确认

此项是对“用户强制发送说明”的安全实现：开启自定义主题补充→本地删除姓名/学校/联系方式/单位/精确金额日期等→人工确认抽象主题→合并为计数达到k的主题分布→弹出第二次确认“本次含经处理的原因主题”→重新展示完整请求→最终确认。任何原始逐条说明、引文或单人故事都不得发送，二次确认不能解除第一章“不发送原始明细”的硬约束。

MVP可先提供本地人工归类主题和计数；无法可靠处理时不发送该模块，不能让云端先看原文再帮忙脱敏。

### 18. 【新增】DeepSeek API接入设计

#### 18.1 官方资料核查与模型兼容

核查日期2026-09-26。当前官方首页和Chat Completions文档列出deepseek-flash、deepseek-v4-pro；官方更新日志曾公告deepseek-chat/deepseek-reasoner于2026-07-24停用。不能把用户给出的旧名称硬编码为永久可用，也不能仅凭公告推断每个Key的实际响应已测试。

#### 18.3 请求及响应契约

默认：HTTPS POST https://api.deepseek.com/chat/completions；Content-Type: application/json；Authorization: Bearer <用户Key>。原生fetch足够，禁止为浏览器SDK方便而引入网站转发后端。credentials=omit、referrerPolicy=no-referrer、redirect=error、cache=no-store；无业务数据放查询参数；只允许文本messages，禁止files/images/tools及附件上传。

正文仅包括预览过的model、messages、stream=false、max_tokens及能力表允许的temperature/thinking等参数。messages只有固定system提示词与本次SanitizedAiPayload序列化文本，不附加历史对话、原始表格、隐藏system上下文或真实身份字段。初期非流式，后续流式需单独验收并沿用相同确认边界。

请求由唯一network adapter发出，接收一次性确认令牌，发送前检查授权hash/版本和目的URL，消费后不可重复使用；同步互斥避免双击双付费。AbortController处理取消/超时；不自动重试、续写、改模型或改端点。

响应校验HTTP状态、可解析JSON、choices[0].message.content类型、内容大小（默认≤1MiB）、finish_reason。只取必要字段；错误正文只提取安全错误码与短说明，不显示整份HTTP报文。AI输出存储和导出仍执行本地安全检查。

#### 18.4 错误处理

| 情形 | 用户提示与动作 | 网络约束 |
|---|---|---|
| 无Key/未解锁 | 先配置或解锁，返回重新预览 | 不发请求 |
| 参数非法/400/422 | 检查模型能力、参数和摘要长度 | 不盲目重发 |
| 401 | Key无效或认证失败，建议替换 | 不打印Key |
| 402 | 余额不足，用户自行处理 | 不自动查询余额 |
| 模型不存在/不可用 | 显示模型ID及兼容提示 | 不静默切换 |
| 429 | 请求受限，稍后手动重试 | 不后台排队重发 |
| 500/503 | 服务暂不可用 | 返回预览后手动重试 |
| 网络失败/疑似CORS/TLS/DNS | 浏览器无法读取响应，展示排查方法 | 不宣称已确定CORS；不自动代理 |
| 超时/取消 | 本地已停止等待，可能已产生费用 | 新调用必须再确认 |
| 非JSON/空content/响应超限 | 返回内容异常或不可用 | 不将错误HTML渲染为报告 |
| finish_reason=length等 | 结果不完整，标注后可本地保留 | 不能自动续写 |

浏览器fetch常无法让应用区分CORS、断网、TLS等根因，最终说明应允许“疑似CORS，需查看开发者工具”，而不是所有TypeError均显示CORS。诊断信息不可带Key或敏感正文。

#### 18.5 CORS与可选代理

直连Authorization与application/json通常需要浏览器预检；服务端必须允许实际Origin、POST及Authorization/Content-Type等头。不能用mode:no-cors解决，也不能要求用户关闭浏览器安全策略。

失败后保持本地功能可用，允许复制已预览的安全摘要；提供“可选本地代理模式”或用户自有代理配置说明，但不自动启用、不使用公共CORS代理、不经过网站运营方服务器。

本地代理作为**用户单独安装/运行的可选组件**，不是默认静态网站后端。建议仅绑定loopback、校验Host/Origin、限制为此站点来源、使用本地随机访问令牌、仅允许固定DeepSeek上游和路径、禁用请求/Key日志、不落盘、不开放到0.0.0.0。HTTPS站点访问本地端点可能受混合内容/本地网络访问权限限制，按目标浏览器实测，不能宣称装代理必通。

自有远程代理只能由用户主动配置HTTPS地址、单独确认其归属与数据边界；代理可以看到Key和摘要，必须在预览明确列为接收方，不能仍宣传“只有DeepSeek接触”。网站运营方不得托管该代理。更换端点撤销所有旧授权及Key转发许可；Key按端点绑定，不把直连Key自动发送到新地址。无代理信任确认则只能直连。

MVP交付直连与失败提示、自有代理说明；代理程序本身放到后续可选迭代，不在此次提示词中自动创建后端。

#### 18.6 CSP、离线与发布配置

原connect-src 'none'会阻止DeepSeek。提供两种构建配置：仅本地版维持none（PWA静态资源按既有规则处理）；含可选AI版connect-src精确允许https://api.deepseek.com，若PWA确有必要再允许固定同源资源。可选代理只在明确构建配置中加入指定来源，不能用*、任意https:或运行时字符串绕过CSP。

AI默认关闭的运行时开关不是网络防火墙；CSP只限制目的地，也不能替代用户确认。应用层以一次性授权、严格payload契约和测试确保默认零DeepSeek请求。已有响应头/meta CSP不能靠追加宽松meta放宽，平台需一致配置并实测。

Service Worker只缓存静态应用壳，明确绕过DeepSeek/代理请求与响应；不缓存Authorization、不后台同步、不离线排队、不恢复网络后自动发送。离线可浏览本地看板及已解锁历史，AI发送不可用。
