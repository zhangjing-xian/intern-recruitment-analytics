# 演示数据（合成）

本目录的文件用于**手工体验**当前版本的功能，不参与构建，也不会被打包进网站。

## 数据来源与红线

- 全部为**人工构造的合成值**：城市 / 岗位 / HR / 学校 / 推荐人都是「样例」「合成」这类明显假的名称。
- **不含**任何真实姓名、真实薪资、真实 HR、真实学校、真实需求 ID（AGENTS.md §2.6）。
- 生成方式不是手写，而是按项目**唯一的 21 列契约**（`src/domain/template.ts` 的 `TEMPLATE_COLUMNS`）拼行，
  因此格式与网站里「下载标准模板」逐字节同源，不会因为列序漂移而导入失败。

## 怎么用

1. 打开网站 → **导入数据**页。
2. 把 `demo-intern-recruitment.tsv` 的内容**整个粘贴**到「粘贴表格」文本框，或直接选择该文件上传。
   （制表符分隔，50 条记录 + 1 行表头。）
3. 进入**字段映射**页：这份数据用的是标准表头，21 列会被自动识别、无需手工指定。
4. 进入**清洗预览**页：检查问题与重复，然后**提交**清洗结果。
5. 之后可以依次看：
   - **分析看板**：KPI、状态结构、时间趋势、分维度分析、质量提示、记录明细；
   - **拒 offer 专项**：两组口径卡片、原因分布（刻意做了「填了原因」「未填原因」「字典外的自由文本」三种，用来演示填写率与「未分类」提示）、关注标签、行动建议；
   - **报告导出**：预览脱敏后的字段与抑制说明，再导出 XLSX / Markdown 或打印成 PDF。
6. 若想试**筛选**：看板、拒 offer 专项、报告导出三页共用同一套筛选口径，改一页三页一致。

## 重新生成

```bash
npx vitest run src/demo
```

`src/demo/demoDataset.test.ts` 会按模板契约重新写出 `demo-intern-recruitment.tsv`
（写成测试是有意的：这样 `npm test` 会顺带保证演示数据与列契约不漂移）。
`src/importers/_demoData.test.ts` 则反过来验证这份文件真的能被解析、表头完全匹配、21 列全部自动识别。
